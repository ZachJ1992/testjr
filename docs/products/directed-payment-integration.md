## 三、模块任务分配

| 模块 | 负责Agent | 主要任务 |
|------|-----------|----------|
| 系统管理 | Agent A | 权限定义、虚拟账户基础设施、付款码表 |
| 合同管理 | Agent B | 合同CRUD、支付类别配置、自动支付配置 |
| 结算中心 | Agent C | 结算单生成、利息计算、还款处理 |
| 资源管理 | Agent D | 运单集成、手动/自动支付触发、TMS对接 |

详细任务说明见各模块文档。

## 四、接口依赖关系

### 4.1 模块间调用关系

```typescript
// 资源管理模块 调用 合同管理模块
import { getContractByFinancierId, getPaymentCategories } from "./contract-module";

// 资源管理模块 调用 系统管理模块
import { createPaymentCode, getVirtualAccount } from "./system-module";

// 结算中心 调用 合同管理模块
import { getContractById, updateContractUsedAmount } from "./contract-module";

// 结算中心 调用 资源管理模块
import { getPaymentsByContract } from "./resource-module";
```

### 4.2 共享Store函数

各模块需要实现的 store 函数将在各自的任务文档中定义，主Agent负责整合到 `backend/src/store.ts` 或创建独立的 store 文件。

## 五、开发顺序建议

```
Phase 1（并行）:
├── 主Agent: 数据库表结构、类型定义
├── Agent A: 权限定义、虚拟账户基础
├── Agent B: 合同基础CRUD
└── Agent C: 结算单基础结构

Phase 2（并行）:
├── 主Agent: 支付审批流程、执行引擎
├── Agent A: 付款码功能
├── Agent B: 支付类别配置、自动支付配置
├── Agent C: 利息计算、还款处理
└── Agent D: 运单集成、支付触发

Phase 3（并行）:
├── 主Agent: API路由整合、联调测试
├── Agent B: 合同前端页面
├── Agent C: 结算前端页面
└── Agent D: 运单页面集成、TMS对接

Phase 4:
└── 全员: 联调测试、Bug修复、优化
```
